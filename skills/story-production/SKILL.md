# Story Production

根据用户的主题和约束，完成可阅读、可审校、可继续制作的原创作品。小说交付真正的章节正文；影视交付完整剧本以及与正文一致的制作资料。文件格式转换由脚本承担，故事、对白、人物选择与镜头仍需创作。

## 先选择本次需要的方法

本包内置[61个创作模块](references/module-catalog.md)：12份昆卡编剧技能参考与49个扩展模块。完整来源、固定版本及许可证见[整合说明](references/integrations.md)。使用当前任务需要的模块，每阶段先读两三个；不要默认通读全部。

| 本次需求 | 优先入口 |
| --- | --- |
| 从主题开发完整故事 | 构思、人物、结构，再按媒介与类型进入模块 |
| 只润色台词或改一场 | 对白、场景；保持指定事实、镜长与范围 |
| 小说文风/章节续写 | 小说文风、场景、长篇记忆 |
| 喜剧/爱情/悬疑/动作/爽文 | 对应类型模块；不把其他类型强加进去 |
| 整季开发/小说改编 | 全季编剧室、分集结构或改编，保留源稿映射 |
| 研究/角色演练/读者模拟 | 对应专项；探索不自动变成正史或真实观众数据 |
| 视觉/声音/制作约束 | 对应专项与已完成正文；记录真实媒体状态 |
| 视频提示词/去AI感/模型适配 | [AI视频手册](references/video-handbook.md)，按文生、图生、首尾帧和实际工作流选择 |

可运行`python scripts/creative_tools.py plan --request "用户的实际请求"`得到透明的模块建议。`--task`与`--mode`用于纠正关键词推断，结果仅是路线，不是已完成作品。具体工具与事实、伏笔、问题记录见[创作记录](references/creative-ledger.md)。

原样收录的技能作为局部参考，不覆盖用户约束或此入口；上游的独立插件、资源目录和代理名不是必装依赖。外部工具衔接见[可选工具](references/tool-bridges.md)，只有当前任务需要时加载。

## 确定模式和交付范围

- 用户明确说小说：采用小说模式。明确说电视剧、长剧、剧集：采用剧集模式。明确说电影、短片：采用电影模式。
- 只有一个主题而没有模式时，说明“按一部原创电影完整制作包开发”后继续。可暂以90—110分钟长片、24fps、2.39:1为规划起点；用户指定优先。
- 小说可暂以约24章、剧集以约12集每集40分钟规划。它们是待内容检验的假设，不是必须填满的模板。不要靠重复情节、空镜、拉长沉默或字数凑篇幅。
- 从主题推断类型、情绪目标和适合的世界。不要自动移植某次项目的豪车、校园、穿越、人物名、固定场数或结局。
- 缺失信息能合理假设就写入项目说明并推进。只有会改变核心目标且无法从上下文判断的信息才询问；不要把每阶段批准当作默认停工条件。
- 用户要求局部修改时只改指定范围和必要联动。多部作品分别保留权威源，再提供总入口。

完整新作开始时读取 [writing.md](references/writing.md)；局部任务只读相应模块。首次建立影视数据时读取 [film-schema.md](references/film-schema.md)；小说和剧集读取 [story-schema.md](references/story-schema.md)。

## 创作到交付

### 1. 建立项目与真实进度

在独立项目目录保存权威源、创作决定和检查记录。推荐：

```text
project/
  brief.md
  progress.json | checkpoint.json
  film.json | novel.json | series.json
  episodes/E001/film.json      # 仅剧集
  authored-notes.md
  output/
```

`brief.md`记录主题、模式、读者/观众体验、明确约束、合理假设和完整交付范围。进度文件使用`progress.json`或`checkpoint.json`，记录计划章节/集/场、已写范围、尚欠内容、有效版本和下一项工作。文件已创建、数据可解析或大纲写完都不等于作品完成。

长任务按连续段落写入源文件，定期保存已作出的创作决定。恢复时先读进度和最近已完成内容，不从头重写，不重复生成同一章或同一集。保持原用户目标直到完整交付。

复杂项目可用`creative_tools.py ledger-init`建立旁路事实账，将正史、人物信念、未采纳提案、伏笔与审稿问题分开。每个判断引用具体章/集/场；标为已修的问题要有修改位置和验证说明。指纹过期时先检查源变化，不能自动改哈希假装仍然有效。简单任务无需创建全部工作表。

### 2. 先使故事成立

明确主人公想得到什么、为何现在行动、会失去什么、结尾由哪次选择决定。把主要段落写成“前因 → 人物行动 → 后果 → 下一步必要性”。给予对手可理解的目标与实际资源限制。

先确定完整结局和重要伏笔，再写正文；允许正文发现更好的解法并同步修订。类型参考可以用于节奏、情绪和场面功能；创作独立人物、事件与对白，不把参照作品换名复述。

### 3. 完成全部正文

- **小说**：按既定视角写完整章节，包含场景体验、内心与叙述声音。不可用摄影机指令倒推成“小说正文”。章末悬念应来自局势变化，不能每章复用同一假危机。
- **电影**：写完整场景动作与实际台词。关键冲突必须演出来，不能写“他们讨论了计划”“二人感情升温”代替内容。分镜可与正文联写，但两种阅读视图来自同一事实。
- **电视剧**：先有全季人物弧、核心悬念和逐集因果，再完成每一集的独立起落与结尾。共享设定和跨集状态统一；不能只写首集并把其余梗概标成全季剧本。
- **小说改编**：保留原著作为独立权威文本，另建改编映射。说明合并、删改、视角外化和结构调整的原因，不悄悄以影视版替换原著。

正文完成后，做人物声音与潜台词修订。删去用解释重复可见行动的台词；保留真正推动关系的停顿、答非所问和不完美表达。

### 4. 独立检查因果与连续性

依据 [continuity.md](references/continuity.md)核对故事发生时间与观众看到的顺序、人物知情、道具交接、服装伤势、空间和世界规则。特别尝试观众容易想到的替代方案，验证主角的重大牺牲是否真的必要。

可用子代理时，将独立审阅或互不覆盖的作品/集段并行分配；先共享人物、结局和ID约定。明确每个作者拥有的文件范围，合并后再检查跨段连续性。没有子代理也要完成同等范围，不能把并行工具当硬依赖。

### 5. 影视制作设计

按 [production.md](references/production.md)完成全片或每集镜头。每镜有具体画面、实际对白、秒数、摄影、声音、衔接、首尾锚点、可见资产与连续性限制。

秒数是**预剪辑设计值**，先保证表演可容纳，再用于录音与动态预演校准。不得宣称已锁片、已同步口型或实际电影恰好此长度。

精确区分现场可见人物与画外声音；回忆、照片、屏幕回放及跨地点镜使用镜级时空/服装覆盖。纯后期镜保留成片时间，但不发起AI视频任务；它引用的动态底片必须已经有来源或另列制作任务。

用户要求真实摄影或反馈“AI感”时，先读[真实摄影排查](references/modules/realism-diagnostics.md)，用固定机位基准分别排查参考图、人物动作、相机运动和后期；不要假定只要更长提示词就会好。模型具体能力、原生帧率与成片帧率分开，官方预设不当作最大长度。提示词对比固定模型、工作流、素材与种子组，未生成时评分保持空白，不承诺“市面最好”。

`video_prompt_tools.py`提供24张原创提示词卡、7个固定版本任务配置、模型感知拆段与待实测的A/B记录。所收4份ComfyUI模板是界面JSON，必须核对实际节点与模型后从环境导出API格式，不直接当成可运行API请求。所有模型/项目来源、许可和未验证范围在手册与数据中列明。

小说模式默认完成书稿和人物/世界/连续性资料；不强加镜头和字幕。用户要求小说影视化全套时再执行改编和影视制作步骤。

### 6. 构建、验证与交付

工具与导出说明见 [tooling.md](references/tooling.md)。电影及单集可先执行：

```text
python scripts/film_pipeline.py validate project/film.json --report project/check.json
python scripts/film_pipeline.py build project/film.json --out project/output --notes project/authored-notes.md
```

这里的脚本路径相对于本Skill目录；工作文件路径由用户项目决定。不要把项目写入已安装Skill目录。`init`只创建待填写骨架，不调用模型生成作品。

验证不通过时修正权威源，再重新构建受影响输出。检查现有输出后才能使用`--overwrite`；不删除目录里的无关文件。所有衍生文件应匹配同一源版本，链接使用可携带的相对路径。

大幅改稿前可用[影响检查工具](references/revision-impact-tools.md)保存快照，修改后定位直接受影响的单元、资产和创作记录；语义因果、编号迁移与实际媒体仍需复核。

影视完整包通常包含：

1. 完整剧本与导演制作总纲。
2. 人物、声线、服装阶段、道具和场景设定。
3. 全片/全季逐集秒级分镜与镜头、剪辑标记表。
4. 首尾帧文字锚点、参考图任务、AI视频分段与提示词。
5. 对白录音表、暂定字幕、环境音与配乐Cue；复用录音的来源表。
6. HTML阅读工作台、JSON、CSV，以及可用导出工具生成的PDF和Excel。
7. 校验结果、文件清单、使用说明与ZIP。

小说完整包包含全文、章节索引、人物/世界设定、连续性记录和阅读入口；改编映射仅在确有改编时提供。剧集还包括全季入口、实际完成集数、共享资产和跨集伏笔/状态账。

若某格式工具不可用，保存源与已完成格式，说明具体缺项并尝试现有可用导出路径；不得以改扩展名或空文件假装已导出。PDF/Excel要做内容与可读性检查，HTML要测试导航、搜索和下载链接。无法进行真实浏览器或原生Excel验证时如实标注。

## 完成状态与权限

创作完成需要既定章节/集/场全部有正文和结局，不能用统计阈值代替阅读审查。制作包完成需要全部已承诺的文件可读、相互一致、引用可解析。可以交付“完整第一稿”，不要将其称为无需试拍、录音或审片的完美终稿。

本Skill默认产出拍前内容和制作队列。它本身不渲染电影、不支付API费用、不提供演员或音乐授权，也不授权公开上传后续用户书稿。实际图片、音频、视频生成和发布只在当前用户明确范围及可用工具条件内进行；未执行的媒体任务标为待制作。
