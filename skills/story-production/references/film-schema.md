# 电影与单集权威数据

`film.json`同时驱动文学阅读视图和拍前制作视图。不要在输出的CSV或HTML里单独修改故事；修改源后重新构建。以下是字段说明，不是可以当作完整作品的示范正文。小型可运行数据见`assets/example-film.json`。

## 顶层字段

| 字段 | 结构与意义 |
| --- | --- |
| `slug` | 项目文件标识，建议小写字母、数字和连字符 |
| `title`, `genre`, `logline`, `theme` | 片名、类型、一句话故事、主题 |
| `synopsis` | 包含实际结局的完整故事摘要 |
| `world_rules` | 影响人物选择的世界规则数组 |
| `characters` | 人物资产，见下文 |
| `props` | 道具/车辆/船等可见物资产 |
| `locations` | 地点及固定空间设定 |
| `structure` | 段落因果与伏笔安排，不代替场景正文 |
| `production` | 本片视听与AI制作策略 |
| `continuity_audit` | 已核对的关键链条及依据 |
| `scenes` | 全部场景，按呈现顺序连续编号 |
| `project` | 可选的范围与技术规划 |
| `authoring_status` | 创作骨架为`incomplete`，完成后设为`complete`；未完成源不能构建为交付包 |
| `recurring_audio_cues` | 可选，同一声音在不同镜重复出现的唯一来源关系 |

推荐`project`：

```json
{
  "format": "feature",
  "language": "zh-CN",
  "fps": 24,
  "aspect_ratio": "2.39:1",
  "target_minutes": 100,
  "credits_seconds": 120,
  "max_clip_seconds": 8
}
```

`format`支持`feature`、`short`、`episode`。帧率使用脚本支持的整数值，常用24、25、30；不是丢帧时码。目标时长是规划约束，实际时长来自镜头合计。8秒是可调制作分段建议，不是某个视频模型的能力声明。

人物示意：

```json
{
  "id": "C01",
  "name": "角色名",
  "age": 28,
  "appearance": "独立外形与固定辨识特征",
  "voice": "音色、语速、语言习惯",
  "want": "外在目标",
  "need": "内在改变",
  "arc": "起点、代价、决定、结局",
  "costumes": {
    "A": "当前日常造型",
    "B": "下一时段或事件后的具体造型",
    "P": "过去造型，仅当剧情需要时设立"
  }
}
```

`props`元素使用`id,name,design,flow`；`flow`标明持有者、交接与状态变化。`locations`元素使用`id,name,geography,look`；固定出口、方位和材质在此定义。所有资产ID唯一，角色和物件不得碰撞。群众如果重复可辨，也给稳定资产身份，不每场重新造脸。

`structure`元素通常为`{scenes,cause,payoff}`。`production`至少描述`palette,camera,sound,music,ai_workflow,priority_tests`，其中验证镜指向本片真实镜号。`continuity_audit`元素为`{thread,setup,payoff,result}`，记录事实与编号。

## 场景

```json
{
  "n": 1,
  "heading": "内 · 地点 · 夜",
  "story_day": "第1天，21:30；或明确的过去时段",
  "location_id": "L01",
  "intent": "本场谁争取什么，结束时发生何种变化",
  "space": "人物初始位置与出口关系",
  "axis": "主视线、运动方向及换轴方式",
  "light": "真实动机光源与明暗关系",
  "performance": "节奏与可表演的情绪方向",
  "sound": "环境声、声源位置与音乐进退",
  "continuity": "进入状态、交接、损伤及离开状态",
  "costumes": {"C01": "A"},
  "shots": []
}
```

每场必须有实际镜头；空数组只允许存在于尚未完成的创作骨架。`n`从1连续递增，镜号由场与场内序号确定，例如`S01_001`。在修改中插入镜头后，重建所有下游引用，不手工沿用过期镜号。

## 每镜12字段，顺序固定

| 下标 | 内容 |
| ---: | --- |
| 0 | 成片时长秒，正数；建议先用整数秒，之后按项目帧率校准 |
| 1 | 景别 |
| 2 | 全画幅等效焦段mm，纯后期写0 |
| 3 | 摄影机位置和运动 |
| 4 | 具体画面、行动和表演 |
| 5 | 实际对白数组，形如`[["说话人","完整台词"]]`；无对白为`[]` |
| 6 | 声音、音乐及画内/画外关系 |
| 7 | 剪辑衔接 |
| 8 | 首帧静态锚点 |
| 9 | 尾帧静态锚点 |
| 10 | 本镜可见角色与物件ID数组 |
| 11 | 特定连续性和AI制作限制 |

“某人（画外）”“某人录音”“某人（电话）”“某人（未来声）”写在说话人字段中，并在声音字段明确声源。可见资产数组只列实际入画实体，不能因为台词说了某人的名字就加入脸参考。对白先后顺序即播放顺序；时间自动分配只是暂定录音区间。

首尾锚点描述两个可检查的构图状态，不把多段动作都写进首帧。静止镜可以首尾相同，但需要叙事理由；动态镜不能靠同一句“承接上镜”掩盖空间缺失。

## 镜级覆盖

跨地点、回忆、过去影像及同场中的造型变化使用`shot_overrides`。键是场内镜号的字符串；只覆盖本镜，未覆盖的内容继承场设定。

```json
{
  "shot_overrides": {
    "3": {
      "location_id": "L02",
      "space": "只见过去工作室，当前客厅不进入底片",
      "axis": "过去素材既定方向",
      "light": "过去的日间窗光",
      "continuity": "同一人物的过去时态，无当前伤口",
      "costumes": {"C01": "P"}
    }
  }
}
```

服装覆盖与该场服装映射合并，不应意外删掉同镜其他人物的服装。`location_id`必须指向已定义地点，造型阶段必须存在于对应人物的`costumes`。

## 同一声音复用

```json
{
  "id": "Q1",
  "text": "在两次出现中逐字一致的完整台词",
  "heard_shot": "S01_003",
  "source_shot": "S02_005",
  "heard_story_time": "第1天夜",
  "source_story_time": "第2天18:00:00—18:00:08",
  "local_in_sec": 0,
  "duration_sec": 8,
  "notes": "先录真实来源的完整八秒，再原样复用；听者不对录音做口型"
}
```

镜号必须存在，台词必须在两镜实际对白里各出现一次，片段不能超出任一所属镜时长。同一镜内多段复用Cue不能重叠。时长和镜内入点按项目帧率对齐；完整片段包含需要的呼吸、静默和环境，不只复制文字。8秒并非强制值，应与本片规则一致。

## 构建输出的时间含义

每镜入点、出点、帧号都从权威源重新计算。出点不包含该帧；相邻镜前镜出点等于后镜入点。纯后期秒数与AI分段可用秒数之和等于正片设计时长，片尾独立列出。

若改变镜长、对白、结构或资产状态，需要同步重建字幕、提示词、素材队列与工作台。Excel是方便调整的工作视图，不能假定修改它后静态JSON或SRT会自动改变。
